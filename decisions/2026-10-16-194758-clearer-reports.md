# Clearer review and handover reports

Issue: #32

Fresh-eyes reports and handovers were long and put everything at the same weight, so what Skye had to act on was mixed in with what was only there for the record. Both now lead with what needs her.

- **Fresh-eyes buckets are Fix, Needs you and Dropped,** replacing Act on, Consider, Noted and Dropped. Every Fix gets a suggested fix, and every Needs you a recommendation, so the report says what to do as well as what's wrong.
- **Noted is gone.** It was true but needed nothing, so it never changed what Skye did. A finding worth her attention goes under Needs you; anything else isn't reported.
- **Dropped stays, as a plain list.** It's the only trace of findings judged wrong, so it's how Skye catches a wrong judgement. It isn't folded into a `<details>` block, because chat shows HTML as raw tags; both reports use only headings, bold and lists.
- **Each finding's answer is on its own indented line** (Suggested fix, Recommend, Fix, Why), so the problem and what to do about it read apart.
- **Emoji mark each finding's answer:** ➡️ on Recommend and 🔧 on a fix still to make (what Skye acts on), ✅ on a Fix that's done. In a dense report, a fixed icon is something the eye can jump to. One per kind of line keeps the meaning fixed, and Dropped's Why gets none, so it reads as lower priority. The idea of emoji callouts comes from **Matt Pocock's skills** ([mattpocock/skills](https://github.com/mattpocock/skills), MIT).
- **The handover reuses the words:** Needs you, Fixed (with how, why and the commit's sha) and Dropped, so the same word means the same thing in both. Needs you comes first because it's what Skye acts on. Out-of-plan Fix findings move to Needs you, recommending a new issue.
- **No shared template** between the two: the handover adds what fresh-eyes can't know (the fix's sha, whether a finding is in the plan).
- **Shorter handover:** Branch, Covers and Compared with each get a line; Review it is gone, since the base is on the Compared with line; and What changed is one line per file, with files that share a change sharing a line. #20's handover, rewritten this way, went from 694 words to 401. The how and why on each Fixed line, and the labels that separate them, are what keep it above half.
- **Covers names only the short sha,** and `/ship` expands it with `git rev-parse --verify` before comparing. If the short sha ever matches more than one commit, git errors and `/ship` stops, so it fails safely. "The branch tip" went too: it's always true when the handover is posted, and `/ship` catches a branch that has moved on since.
- **Plain paths in chat as well as in the comment,** so chat shows exactly what's posted. Links in chat were clickable, but made the two differ, and links on GitHub would be broken while the branch is local.

Left out: rewording older decisions that mention Act on, Consider and Noted.
