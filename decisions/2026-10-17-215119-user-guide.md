# A user guide and docs pages

Issue: #28

The README listed every skill but showed the order only in one dense line, so learning the workflow meant reading the SKILL.md files. `docs/guide.md` now walks through it, and each skill will get a page in `docs/skills/` for its finer points.

- **In `docs/`, outside the skill folders.** `install.sh` links whole skill folders into `~/.claude/skills/`, so a page inside one would be installed, where Claude might read it while running the skill. These pages are for people, like the README (`2026-10-16-135153-new-project.md`).
- **By phase, not a table.** The guide follows the order the skills are used in (set up, each issue, along the way, housekeeping), because showing that order is its job. The README's Skills tables stay the reference.
- **One line per skill.** The guide stays lean by linking out: to the skill's docs page, or to its SKILL.md until the page exists.
- **Pages link to SKILL.md for the steps.** A page that restated the steps would go stale each time one changed, so pages cover when to use a skill, what you'll see, its gotchas and the reasons, from `docs/skills/TEMPLATE.md`.
- **Kept current by the checklists.** README's "Adding or changing a skill", the `writing-skills` done-checklist and the PR template each ask for the guide's line.

Left out: an automated link checker, and any change to CLAUDE.md, which is for Claude.
